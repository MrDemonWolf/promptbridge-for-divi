## What works in the staging alpha

- An authorized administrator or editor can request a text draft for a Divi Text
  module.
- WordPress stores the request in a private job and rechecks permission and
  consent before starting Codex.
- Codex runs on the WordPress server with a read-only sandbox. PromptBridge
  never runs generated PHP or JavaScript.
- The editor sees an editable preview. The page changes only after the editor
  chooses **Apply to Divi field**.

## What still needs a live test

The app-server protocol is experimental. Real account behavior, host
compatibility, and Divi undo, responsive value, and save/reload behavior still
need testing. See [Limitations and gates](/docs/limitations) before using this
on a production site.

## Plain-English glossary

- **WordPress Cron:** WordPress's built-in scheduler. On a quiet site, a queued
  job may wait until another visit triggers it. A host cron can trigger it on a
  schedule.
- **Dedicated Codex home:** A private folder for this site's Codex sign-in and
  session files. It must be outside the public website folder.
- **stdio:** A local input-and-output connection between WordPress and the Codex
  process. It does not open a port for other computers.

## Protocol detail for developers

The
[Codex app-server documentation](https://developers.openai.com/codex/app-server/)
describes newline-delimited messages over stdio. The CLI still labels this
command experimental, so pin and test the exact Codex version before relying on
it in production.
