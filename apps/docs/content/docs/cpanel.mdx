## 1. Ask the host owner to check the server

Confirm that the site uses PHP 8.3 or newer, allows <code>proc_open</code>, and
can run the installed Codex CLI from the PHP worker. The PHP version and paths
used by PHP-FPM can differ from the command line.

Create a dedicated Codex home for the site. Keep it outside the public website
folder and make it writable only by the site owner/PHP worker. Sign in to this
home yourself. Never copy credentials from a developer account.

## 2. Make sure queued jobs can run

WordPress Cron starts queued work when WordPress gets a visit. On a quiet site,
a job may wait. If your host disables WP-Cron or blocks loopback requests,
configure a cPanel cron to visit

<code>https://your-site.example/wp-cron.php?doing_wp_cron</code> every few
minutes. Replace the example domain with your site and follow your host's
scheduling instructions.

Generation may fail if the host blocks <code>proc_open</code>, outbound API
access, or the time Codex needs to respond. PromptBridge does not install or
update Codex, and it does not expose Codex App Server on a network port.

## 3. Test one page safely

Use a disposable Divi Text module. Request a draft, check that the job runs,
review the preview, choose whether to apply it, then save and reload the page.

If a job fails, check the host's PHP error log and the WordPress Cron schedule.
This checklist helps diagnose one staging site; it is not evidence that cPanel
is supported.
