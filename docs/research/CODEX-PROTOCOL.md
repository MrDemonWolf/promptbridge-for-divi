# Codex Protocol Research

- Status: research baseline; not a production sign-off
- Accessed: 2026-09-21
- Selected Codex release: not yet pinned

## Decision

PromptBridge may prototype against the documented Codex app-server over local
`stdio`, but the integration remains gated because OpenAI describes the
app-server command as experimental and unsupported for production workloads. The
PHP client must use schemas generated by the exact Codex release it supports.
Documentation examples are not a substitute for those release-generated schemas.

## Confirmed facts

1. **App-server is documented, but experimental.** OpenAI documents app-server
   as the interface for rich Codex clients, including authentication,
   conversation history, approvals, and streamed agent events. The same page
   says the app-server command and WebSocket transport are experimental and are
   not supported for production workloads.

2. **Local `stdio` is the default transport.** App-server uses bidirectional
   JSON-RPC 2.0-style messages with the `jsonrpc` member omitted on the wire.
   The default transport is newline-delimited JSON over `stdio`. WebSocket and
   Unix-socket transports are also documented, but PromptBridge does not need
   them.

3. **The documented lifecycle is sufficient for a text prototype.** A client
   initializes the connection, sends the `initialized` notification, starts or
   resumes a thread, starts a turn, reads streamed item/turn notifications, and
   waits for `turn/completed`. Exact request and response fields remain
   version-bound.

4. **Schemas are generated for the running release.** OpenAI provides:

   ```text
   codex app-server generate-ts --out ./schemas
   codex app-server generate-json-schema --out ./schemas
   ```

   OpenAI states that each output is specific to the Codex version that
   generated it.

5. **Managed ChatGPT authentication is supported.** App-server supports a
   browser flow with `type: "chatgpt"` and a device-code flow with
   `type: "chatgptDeviceCode"`. In managed mode, Codex owns token persistence
   and refresh. `account/read`, `account/login/start`,
   `account/login/completed`, `account/updated`, and `account/logout` are
   documented. Successful managed sign-in reports the effective mode as
   `chatgpt`.

6. **Usage data is protocol-supplied, not estimated.** The documented account
   surface includes `account/rateLimits/read` and rate-limit update
   notifications. PromptBridge must show only values returned by the active
   release and must treat missing values as unknown.

7. **Subscription-backed image generation exists in OpenAI-owned Codex/ChatGPT
   surfaces.** OpenAI documents interactive `$imagegen` use and says built-in
   image generation counts against general Codex usage limits. The same page
   directs programmatic image generation to the separately billed Image API.

8. **Image output through a custom app-server client is unproven.** This is an
   inference from the current official docs: the image-generation page does not
   document a custom app-server result contract, and the app-server page does
   not document a generated-image item or binary/file return flow. Absence from
   those pages is not proof that the feature is impossible; it means
   PromptBridge cannot claim support until a pinned release and live
   subscription-backed test return a real image file without an API-key
   fallback.

## Project choices

- The server owner or host installs and updates Codex independently. The plugin
  will never download, install, update, replace, or remove the Codex executable.
- The plugin uses a server-owner-configured absolute executable path, fixed
  arguments, structured `stdin`, and local `stdio`. It will not expose
  app-server on a public TCP or WebSocket listener.
- PromptBridge gets a dedicated `CODEX_HOME` outside public web roots and does
  not reuse the developer's global Codex home. Storage permissions and
  same-operating-system-user risks still require host validation.
- Managed ChatGPT authentication is the only accepted OpenAI mode. Prefer the
  documented device-code flow when supported. Reject API-key, externally managed
  token, and other provider modes rather than silently falling back.
- The login process must remain alive while the user completes the ceremony.
  PromptBridge must verify `account/read`/`account/updated` reports `chatgpt`
  before generation.
- Every supported Codex version requires a checked-in compatibility record
  containing the exact runtime version, generated JSON Schema, and schema
  digest. A runtime version change fails closed until revalidated.
- Image actions remain disabled until the same custom client, using managed
  ChatGPT authentication, is live-tested to produce a validated local image
  file. A separately billed Image API request is not an acceptable substitute.

## Open gates

- [ ] Pin one Codex release and archive its generated JSON Schema plus version
      output.
- [ ] Confirm that the pinned release still carries the documented experimental
      warning.
- [ ] Prove the initialization, managed device-code sign-in, one text turn,
      streamed completion, logout, and rate-limit read against that release.
- [ ] Confirm PHP process control, long-running login behavior, timeouts, and
      cancellation on the target cPanel host.
- [ ] Obtain a WordPress Plugin Review Team answer about directory eligibility
      for a plugin that launches an independently installed local executable
      which contacts OpenAI.
- [ ] Run one small, real image test through the same custom client. Record the
      exact event/item type, file delivery mechanism, MIME/signature validation,
      and allowance impact, or keep the feature blocked.
- [ ] Complete security review for child-process permissions, configuration
      isolation, prompt injection, output limits, and credential storage.
